# 20_PROBLEM — 풀려는 문제

## 핵심 명제

> Claude Code는 강력하지만 **터미널이라는 1차원 인터페이스**에 갇혀 있다. 바이브 코딩 워크플로우의 핵심 자산인 외부 노트·모바일·다른 앱들과의 결합이 *수동* 또는 *ad-hoc 스크립트*에 의존한다.

이 결합 비용 때문에:
- 컨텍스트가 자주 끊긴다
- 자리 이탈 시 작업이 멈춘다
- 작업 결과가 자동으로 자산화되지 않는다
- 멀티 워크스페이스 운영이 어렵다

## 페인포인트 5개 (우선순위 순)

### PP1. 컨텍스트 복붙 지옥 (가장 큼)

**현상**: Obsidian에 정리한 PRD/회고/메모를 매번 직접 복사해서 `claude` 입력창에 붙여넣는다. 코드 결과는 다시 수동으로 노트에 옮긴다.

**빈도**: 일 20-30회

**Yuminai 해결**:
- Vault 자동 탐색 + 노트 클릭 한 번으로 컨텍스트 주입 (`@note-name` 인라인)
- 작업 결과는 자동 또는 슬래시 명령(`/note save`)으로 노트화

### PP2. 세션 휘발

**현상**: 터미널 `claude` 종료 또는 컴퓨터 재부팅 시 대화 사라짐. 어제 어디까지 했는지 직접 git log/노트 뒤져서 복원.

**빈도**: 일 3-5회

**Yuminai 해결**:
- 모든 세션을 SwiftData에 저장
- 워크스페이스 재진입 시 마지막 N개 메시지 자동 복원
- 세션 검색 (전체 텍스트)

### PP3. 자리 이탈 시 단절

**현상**: Claude가 30분짜리 작업 중일 때 외출하면 진행 모름. 돌아와서 화면 깨워야 알 수 있고, 만약 도중에 막혔으면 그 시간 낭비.

**빈도**: 주 5-10회

**Yuminai 해결**:
- Telegram 알림 (이정표 도달, 사용자 의사결정 필요, 완료, 에러)
- 모바일에서 추가 명령 가능 (양방향)

### PP4. 멀티 워크스페이스 병렬 운영

**현상**: 3-4개 프로젝트(`nunchi`, `moodbit`, `emotion-lab`, 디자인 시스템) 동시 진행. tmux/iterm 탭/별도 터미널 창으로 분리하지만 컨텍스트 추적/스위치 비용 큼.

**빈도**: 일상

**Yuminai 해결**:
- 워크스페이스 = 좌측 사이드바 1급 시민
- 각 워크스페이스가 독립된 git 워크트리 + Obsidian 컨텍스트 + 세션
- 빠른 ⌘1, ⌘2, ⌘3 전환

### PP5. 하네스 적용 마찰

**현상**: claude-forge의 rules/agents/skills를 프로젝트별로 다르게 적용하고 싶은데 `.claude/` 디렉토리 셋업이 매번 수동.

**빈도**: 새 프로젝트 시작 시마다

**Yuminai 해결**:
- 워크스페이스 생성 시 하네스 템플릿 선택 (Swift/TypeScript/Python/General)
- `.harness/` 자동 스캐폴딩
- 글로벌 + 워크스페이스 settings 머지 GUI

## 풀지 *않는* 문제 (의식적 제외)

| 문제 | 왜 제외 |
|---|---|
| 코드 편집 자체 | 별도 IDE가 더 좋음 |
| 디자인 작업 | Figma/Pencil 사용 |
| 회의/문서 작성 일반 | Notion/Obsidian 직접 사용 |
| 다른 LLM 사용 | Claude만으로 충분 (멀티 후순위) |
| 협업 동기화 | 1인용 |

## 현재 대안 (Yuminai가 대체할 것)

| 기존 | 한계 | Yuminai 차별 |
|---|---|---|
| `claude` (터미널) | UI 제한, 멀티 세션 어려움 | GUI + 멀티 워크스페이스 |
| `Cursor` 채팅 | IDE 종속, 외부 통합 약함 | IDE 무관, 통합 1급 |
| `Raycast` 명령 | 단발성, 세션 없음 | 세션 영속 + 진행 추적 |
| 직접 만든 Telegram 봇 + 셸 스크립트 | 깨지기 쉽고 컨텍스트 단절 | 통합 인터페이스 |
| Obsidian + Claude API 플러그인 | Obsidian 안에 갇힘, 코드 작업 약함 | 코드 작업 1급 |
